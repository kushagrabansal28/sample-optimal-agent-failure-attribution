## 1. Sample-Optimal Culprit Identification for Agent Failures

**Speaker notes.** Title slide. Introduce both authors. Stress the honest framing up front: the title states the objective, and what we actually prove is δ-correctness of the stopping rule plus a sample-complexity upper bound for one strategy. All reported numbers are from synthetic simulations with exactly known ground truth; the real-benchmark stages (ALFWorld, HotpotQA) are implemented as adapters but have not been run.

## 2. Why agent failures are hard to diagnose

**Speaker notes.** Motivation. Long-horizon agents plan, search, call tools, store memory and answer. When the final answer is wrong, the developer holds a long trace and one question: which step is responsible? The last action is usually a symptom. Cite Zhang et al. (Who&When, ICML 2025, arXiv:2505.00212): the best step-level attribution accuracy they report is about 14 %, which is why LLM judging alone is not a satisfying answer.

## 3. A failed trajectory with a hidden cause

**Speaker notes.** Figure 2 is computed exactly by dynamic programming over the 48-state automaton (no sampling). Steps before the planted fault only exceed the baseline slightly because re-running re-rolls the fault; after the fault the state is corrupted and the repair value falls. The step that maximises the repair value is the culprit under our definition.

## 4. Why last-action or judge-based debugging is not enough

**Speaker notes.** Association is not prediction is not intervention effect is not unique responsibility is not joint cause. We choose one well-defined causal estimand — the repair effect of a single step — and make its estimation statistically rigorous. Other estimands (Shapley credit, direct effects) are different questions and are listed as future work.

## 6. Formal problem: best-arm identification over replays

**Speaker notes.** Arms are the candidate steps. Pulling arm t means: restore the original failed run just before step t, apply the intervention (repair = force the reference action; resample = redraw from the policy), re-simulate to the end, and observe success or failure. Y_t is Bernoulli(μ_t). The target is a function of the means: argmax up to ε, or the first / last step above a threshold θ. Assumptions A1–A6 in the paper make the arms well-defined and the pulls independent.

## 7. Counterfactual replay mechanism

**Speaker notes.** Figure 3 uses a real sampled trajectory. The original run on top is restored up to the chosen step, one action is forced to the reference action, and the continuation on the bottom is re-simulated. One replay equals one sample of the outcome distribution — one Bernoulli pull. Repair vs resample are both implemented; resample is the null intervention and measures intrinsic sensitivity.

## 8. The adaptive algorithm: one round

**Speaker notes.** Figure 4: maintain a confidence interval per step, ask the stopping rule whether the target is certified, otherwise let the sampling rule pick the next step (LUCB picks the leader and its strongest challenger). The sampling rule is interchangeable — δ-correctness depends only on the confidence sequence and the stopping rule. Budget exhaustion is an abstention and is never reported as a certified answer.

## 9. Confidence sequences and the stopping rule

**Speaker notes.** We use a stack-KL confidence sequence, x_n = ln(2Kn(n+1)/δ), intersected over time so intervals never widen. The stop test is lo_h + ε ≥ max over other arms of hi_a. Figure 5 is an actual run: intervals separate and the algorithm stops exactly when the separation margin reaches zero. Stack-KL is never wider than the Hoeffding version (tested) and is slightly looser than the LUCB-rate bound only in constants (ablation).

## 10. Theory: what is proven

**Speaker notes.** Theorem 1: for any sampling rule, the stopping rule built on an anytime-valid confidence sequence is δ-correct — a union bound over arms and time. Theorem 2: for successive elimination, an explicit sample-complexity upper bound of order Σ_a Δ_a⁻² log(K/(δΔ_a)); the full proof is in the paper appendix. Theorem 3: valid prefix reuse. We do NOT claim minimax optimality of any algorithm — the lower bound of Garivier–Kaufmann is used as a yardstick, not matched.

## 11. Prefix reuse: valid vs naive sharing

**Speaker notes.** Figure 10: replays that start later reach the same state at the same time with the same action as another arm's replay would; their remaining trajectory has the same law, so they can be credited to the other arm. We verified Theorem 3 numerically: matched observations agree with the exact value (|z| < 2) while naively pooled observations are biased (|z| about 20–30). In the main experiment naive sharing certifies a wrong answer far more often — shown honestly as a negative control with a small certified sample.

## 12. The 48-state agent automaton

**Speaker notes.** Six groups of eight states: PLAN, OBSERVE, TOOL, MEMORY, VALIDATE, TERMINAL. Seven decision states carry planted faults; corrupted states form a corridor to the failure terminals; recovery edges exist. The state count is validated programmatically (unique ids and labels; the DFA sink is not counted). Larger 64- and 96-state versions are generated the same way.

## 13. Finite-state views of the same specification

**Speaker notes.** DFA: total transition function with an explicit sink, deterministic most-likely view. NFA: all possible successors, so we track active-state sets. ε-NFA: silent self-correction as ε-moves; ε-closure is computed before and after each symbol. Each view is tested: NFA→DFA subset construction and ε-removal preserve the language.

## 14. Probabilistic automaton and labelled transition system

**Speaker notes.** The probabilistic automaton is the natural model of a stochastic agent: each (state, action) maps to a distribution over successors, and the word probability is e_q0ᵀ M_a1 … M_an 1_F. The LTS carries the labelled actions — reasoning, tool use, observation, update, validation, recovery, success, failure — and supports reachability and deadlock analysis. Exact quantities used by the experiments are computed from these kernels.

## 15. Beyond finite state: transducers, PDA, Turing machine

**Speaker notes.** All nine models are implemented and tested. The comparison table summarises acceptance, memory, nondeterminism and fit for agent traces. Important distinction: a finite-state machine cannot recognise arbitrarily deep nesting — a PDA can (our test shows a depth-3 bounded DFA failing on a depth-5 word). The bounded Turing machine reports step_limit/tape_bound as 'unknown', not 'reject'.

## 17. Evaluation pipeline and protocol

**Speaker notes.** Twelve experiment groups, each with 30 paired trials per method unless noted (all methods share seeds so comparisons are paired). Rollout counts of trials that hit the budget cap are censored: means are lower bounds on the true cost. Accuracy intervals are Wilson; rollout intervals are bootstrap; paired tests are Wilcoxon signed-rank with Holm correction over the four primary comparisons. Total simulation time came from suite_meta.json.

## 18. Main result: adaptive allocation needs fewer rollouts

**Speaker notes.** 48-state automaton, 30 paired trials per method, δ = 0.1, budget cap 60 000 rollouts. Bars are mean rollouts; trials that abstained (budget exhausted) are censored at the cap, so uniform/random numbers understate their true cost. Equal-budget and CAR-style fixed-K do not certify anything by design — their rollouts are fixed in advance. LUCB with naive sharing is the invalid negative control.

## 19. Paired statistics with multiplicity control

**Speaker notes.** Each row is a paired comparison on identical seeds. Wilcoxon signed-rank p-values are Holm-corrected over the four primary comparisons; all four reject at 0.05. Ratios are mean-rollout ratios (>1 means the first method is cheaper). 95 % intervals are bootstrap intervals of the paired mean difference. Synthetic data only: these are statements about our simulated benchmark, not about real agents.

## 20. Cost versus gap and the lower bound

**Speaker notes.** Bandit-arm model with K = 8 arms; the best-vs-runner-up gap varies. Cost grows roughly like gap⁻² for uniform allocation (a test checks the log-log slope is between −3.2 and −1.3) and every method stays above the lower bound on average (also tested). The lower bound is a yardstick for an oracle-allocating algorithm: we do not claim to match it.

## 21. Scaling with the number of candidates and with δ

**Speaker notes.** Left: growth of cost with the number of candidate steps K at a fixed gap. Adaptive methods grow slowly because eliminated arms stop being sampled; uniform allocation grows roughly linearly with K. Right: the δ sweep shows the expected mild increase of cost as δ shrinks; empirical error stays at 0 in every cell — consistent with δ-correctness but not a proof (the guarantee is an upper bound).

## 22. Ablations: which design choices matter

**Speaker notes.** One factor at a time on the 48-state automaton, same seeds. Restricting candidates to decision states and using a small ε make the most difference on the planted-fault instances because they remove near-ties between harmless steps; valid prefix sharing gives a large saving at no cost in accuracy. Candidate restriction uses domain knowledge about decision states; it is reported as an assumption-dependent speed-up, not as part of the guarantee.

## 23. Larger automata and violated assumptions

**Speaker notes.** Left: the 48-, 64- and 96-state automata. Prefix reuse keeps the cost almost flat while the plain methods grow with trajectory length. Right: when state reconstruction is noisy (assumption A1 violated) we measure accuracy against the noisy-context argmax and the cost rises; the algorithm abstains more rather than certifying wrongly, and sharing is disabled automatically. This is a robustness stress test, not a guarantee.

## 24. Negative controls and failure modes

**Speaker notes.** Honest reporting: (1) naive sharing is invalid and the experiment shows it. (2) The CAR-style fixed-K rule is a different estimand — it reports the latest step whose effect excludes zero — so its 'accuracy' against the argmax-repair target is not a like-for-like comparison and should not be read as 'CAR is wrong'. (3) Several methods abstain on hard instances; abstention is a feature, not an error. Figure 18 breaks the failures down.

## 29. Limitations and honest status

**Speaker notes.** State plainly what is not done. ALFWorld and HotpotQA adapters exist and are unit-tested with a mock agent, but we have not run them — so no claim about real agents. All performance numbers come from synthetic models with a Markov structure that makes ground truth computable. The OpenAI provider is implemented but untested. Theorem 2 is for successive elimination only. 'Sample-optimal' is the objective, not a result. Novelty is provisional.

## 30. Conclusions and future work

**Speaker notes.** Summary. We turned culprit identification into a fixed-confidence best-arm problem over counterfactual replays, proved δ-correctness for any sampling rule, gave a sample-complexity bound for successive elimination, validated prefix reuse, and measured on synthetic automata that adaptive allocation needs several times fewer rollouts. Future work: run ALFWorld/HotpotQA, tighten the bounds (instance-dependent), Track-and-Stop style allocation, direct-effect estimands with common random numbers.
